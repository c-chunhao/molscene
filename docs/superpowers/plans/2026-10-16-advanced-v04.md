## Review Focus

1. A directory becomes nonempty or an input alias changes between preflight and publish: fail without replacement or source damage (Task 1 race/alias tests).
2. A worker dies abruptly while a tool has grandchildren: all owned descendants exit, no completed bundle appears (Task 2 forced-death tests; Task 6 integration).
3. Random/backward timeline seek after scene edits or a native movie: display inheritance and molecular state remain deterministic (Task 4 scene/native-movie tests).
4. A plausible-looking map has swapped axes, nonzero origin or mixed origin/starts: numerical geometry and explicit interpretation control loading/registration (Tasks 1/3 independent map oracles).
5. A neutral protein or valid zero-radius H is confused with missing parameters, or an ordinary imported molecule is assigned fictitious PQR provenance: preserve valid charges/radii and clearly separate radius models (Task 5 preparation/import tests).

## Frozen shared contracts

### Data, resource limits and reports

All JSON uses UTF-8, finite numbers, exact version/type checks (booleans are not integers), unknown-key rejection and relative artifact paths. Core functions return JSON-compatible `dict`; grid values use `array('d')`. Type aliases below describe fields, not additional modules. Rotation orthonormality/determinant tolerances are 1e-5; affine bottom-row tolerance 1e-8; native matrix/corner verification tolerance 1e-4 Å. Independent science tests specify their own physically meaningful tolerances.

`Grid` in `grids.py` is a frozen dataclass with `shape: tuple[int,int,int]`, `origin: tuple[float,float,float]`, `basis: tuple[tuple[float,float,float],...]` (three basis vectors), `values: array`, `value_unit: str`, `metadata: dict`. Treat values as owned/read-only; copying/conversion returns a new grid. Flat order is `(i*ny+j)*nz+k`; point is `origin+i*basis[0]+j*basis[1]+k*basis[2]`. `grid_metadata(grid) -> dict` returns `shape, origin_angstrom, basis_angstrom, value_unit, statistics{min,max,mean,population_sd}, value_sha256, source_format, interpretation, normalization`; value digest is canonical little-endian float64 values in flat order. `metadata` also retains original MRC header fields, source SHA256 and file-axis mapping.

Initial bounds: input grid <=512 MiB; <=16,777,216 voxels, each dimension 2..4096; timeline <=10,000 frames/keyframes, 1..120 integer FPS, states 1..100,000, JSON <=8 MiB; render width/height 16..4096, product <=16,777,216, DPI 1..1200, estimated raw RGBA sequence <=8 GiB. Tool config <=64 KiB; PQR <=64 MiB/1,000,000 atoms; stdout/stderr each <=16 MiB, probe timeout 15 s, preparation 600 s, solver 1200 s, encode 1200 s (typed configurable execution timeout 1..3600 s). Exceeding a log bound fails the run and retains complete captured bytes up to the bound in private failure evidence; a successful bundle never silently truncates logs.

`RenderSpec = {width:800,height:600,dpi:150,ray:bool=true}`. `Progress = {stage:str,completed:int,total:int,message:str}`; callbacks are `progress: Callable[[dict],None]|None` and `cancelled: Callable[[],bool]|None`, never serialized. `bundles.CancelledError` is the shared cancellation exception. Every stage and publication checks cancellation.

Advanced reports retain `schema_version:2,tool,tool_version,pymol_version,created_at,operation,inputs,parameters,structure,analysis,artifacts`; add `passed:true,replay_contract,snapshot_id,source_fingerprints,advanced_fingerprints,limitations,warnings,artifact_hashes`. `inputs` maps role to `{path:<relative bundle path>,sha256,bytes}`; `artifacts` maps role to relative path or exact ordered frame paths. `artifact_hashes` covers every payload except `report.json` (avoid self-hash recursion); `manifest.json` contains the closed inventory and SHA256/size of every file except itself, including report. Root publication checksums include the final manifest. `snapshot_id` is frozen PSE SHA256 or null when no session was supplied; `source_fingerprints` maps decimal molecular states to existing `scene_fingerprint` values.

`advanced_fingerprints` has `files` (role -> source SHA256), `maps` (name/state -> digest of raw values, physical geometry, effective matrix and source association), `timeline` (canonical document SHA256 or null), `display_snapshot` (source PSE SHA256 or null), `selection` (canonical selected atom identity/coordinates/radii digest or null), `session_epoch` (GUI session generation or null). Never reuse atom-only fingerprints to verify map/scene contents. Timeline reports retain frozen PSE identity for referenced display scenes; without a fresh equivalent display snapshot, current live display equivalence is `unverified`, not `current`. New result-copy application compares the relevant molecule/map fingerprints and epoch; camera movement alone does not stale a potential result.

Progress may additionally contain `pid:positive int` only at `stage='tool_ready'`.
This is the owned guardian process identity for lifecycle diagnostics; all
other stages use the four standard fields. Managed run diagnostics retain that
ownership PID. Consumers must not parse PIDs from human-readable messages.

### Bundle interface and exact inventories

`Bundle(destination:Path, *, protected:Sequence[Path], inventory:Sequence[str], cancelled=None)` is a context manager with `.stage:Path`, `.scratch:Path`, `.failure_path:Path`, `.copy_input(source:Path, relative:str)->dict`, `.retain_failure_logs(logs:dict[str,Path])->None`, `.publish()->Path`. Stage/scratch are unique owned sibling directories; failure_path is sibling `.molscene-failure-<uuid>` and created only on failure. Register role→log-path mappings before running tools; only bounded regular files inside this bundle's stage/scratch are accepted. On failure retain these logs as `logs/<role>.log` plus `failure.json` (operation error/cancel and log hashes), never copied scientific inputs; then safely clean owned stage/scratch. On success remove scratch after copying declared artifacts. This supplies standalone CLI and worker failure evidence without another output option.

`write_manifest(stage, inventory)->dict` hashes payloads. Inventory contains exact file paths, never globs/recursive whitelists. Recheck lexical links/reparse points, types, hardlink aliases and source/job/envelope ancestry before staging/publication. Preserve bytes; compare source pre/post-copy SHA256. Remove an empty destination only with repeated checks and nonrecursive `rmdir`; publish using no-replace directory rename (Windows MoveFile, Linux `renameat2(RENAME_NOREPLACE)`, otherwise fail closed). Race-created directories are never replaced. Failure leaves completed output absent.

Inventories are computed before production and reject unexpected/missing/special files:

The manifest is exactly `{schema_version:1,files:{relative:{sha256,bytes}}}`.
Inventory includes `manifest.json`; its files mapping excludes itself.
`Bundle.publish()` writes and validates this final manifest. Generic bundles
allow empty regular payloads (valid tool logs); operation owners require
nonempty images, sessions, maps, MP4 and other semantic artifacts.

For MRC auto mode, an origin-only file requested as CCP4 is rejected with an
actionable choice of MRC (or explicit starts to ignore ORIGIN). Explicit starts
records source_format=ccp4/interpretation=starts, explicit origin requires MRC.
Keep requested_format metadata when actual loader interpretation differs.

- Timeline project: `source.pse,timeline.json,replay.pml,report.json,manifest.json`.
- Animation: project files plus exactly `frames/frame_000001.png` through the declared final frame; MP4 additionally `animation.mp4,tools.json,logs/ffmpeg.stdout.log,logs/ffmpeg.stderr.log,logs/ffprobe.stdout.log,logs/ffprobe.stderr.log`. PNG-only has no tool artifacts.
- Density: `source.pse` iff session supplied; exactly one `inputs/density.{dx,mrc,ccp4,map}` preserving the source suffix; `density.json,scene.pse,scene.png,replay.pml,report.json,manifest.json`. Registration/alignment metadata lives in `density.json`; aligned models are native copies in `scene.pse`, reproducible from the source session and stored delta in replay.
- Potential prepared: `inputs/source.pqr,prepared.pqr,potential.dx,apbs.in,tools.json,logs/apbs.stdout.log,logs/apbs.stderr.log,scene.pse,scene.png,replay.pml,report.json,manifest.json`.
- Potential preparation: previous solver outputs, replace `inputs/source.pqr` with `source.pse,inputs/selection.pdb`; add `preparation.json,logs/pdb2pqr.stdout.log,logs/pdb2pqr.stderr.log`. PDB2PQR intermediates are private scratch unless explicitly retained inside `preparation.json`; never widen the inventory.
- Potential import: `inputs/potential.dx` plus `inputs/source.pqr` or `source.pse` according to radius source; `scene.pse,scene.png,replay.pml,report.json,manifest.json`. Add `display.dx` only when explicit unit conversion is requested. No fabricated solver files/tool metadata.

Standalone replay PML embeds ordinary Python/JSON data, uses `cmd` and stdlib only, resolves paths relative to its script, and never interpolates scene/selection names into executable command fragments. Timeline replay exposes `molscene_seek(frame)` and `molscene_play()` with the same sampling/display semantics and no solver dependency. Other replay scripts reproduce only their owned result objects; source PSE loading in standalone replay is allowed, applying a worker result to the existing GUI must not load that full PSE.

### External tools configuration

`load_tools(path:Path)->dict`, `probe_tool(name:str, config:dict, *, work_dir:Path,cancelled=None,progress=None)->dict`, and `run_tool(name:str, config:dict, args:list[str], *, cwd:Path, log_prefix:Path, cancelled=None, progress=None)->dict` live in `external_tools.py`. Probes forward cancellation/progress into their managed runs. Config schema 1 has exactly `schema_version,tools`; tools contains optional `apbs,pdb2pqr,ffmpeg,ffprobe`. Each entry has `argv:list[str]`, `architecture:'x86'|'x64'`, `path_dirs:list[str]`, `runtime_files:list[{path:str,role:'dll'|'interpreter'|'package_metadata'}]`, `timeout_seconds:int`, `memory_limit_mib:int`. Paths are absolute, existing, lexically checked; `argv[0]` is an executable file, never shell/batch/PowerShell. Other argv entries are literal fixed prefixes (e.g. `-B,-m,pdb2pqr`); operation arguments are appended separately, no formatting placeholders. No arbitrary environment dictionary or command-string editor.

Child-only PATH uses configured `path_dirs` plus platform system directories; never modify parent PATH/HOME/USERPROFILE/registry. Clear `PYTHONPATH,PYTHONHOME,VIRTUAL_ENV,CONDA_PREFIX`, set `PYTHONNOUSERSITE=1`, and direct child TEMP/TMP to owned F scratch locally. Process provenance records actual argv, executable/runtime-file SHA256, parsed version, architecture, exit code, elapsed seconds, logs and package metadata hashes. APBS `--version` exit 13 is accepted only with recognized 3.4.1 text; solve exit must be 0. PDB2PQR external Python must actually report >=3.11; a config label cannot substitute for probing runtime architecture/version.

Guardian protocol: worker launches `python -B -m molscene.process_guardian <request.json>` with stdin as a private keepalive/control pipe; request contains version 1, argv, cwd, constructed child environment, log paths, timeout and limits. Guardian reports bounded JSON-line `ready/result/error` records on stdout. It establishes its ownership boundary before tool spawn: POSIX new session/process group, Windows guardian assigns itself to kill-on-close Job Object before any descendant starts. Tool cannot inherit the keepalive pipe or Job handle. Worker closes pipe on cancellation; EOF on abrupt worker death also triggers cleanup. Guardian terminates/waits owned descendants, escalates within 2 s, then exits; worker waits for guardian. No assign-after-tool-spawn race, executable-name killing or `taskkill`. Forced guardian death must also terminate Windows Job descendants; POSIX worker guardian-death detection kills the recorded owned group while worker is alive. Test the required worker-death contract on both platforms.

APBS allowed counts per axis are `{33,65,97,129}` on x86, plus `{161,193}` on x64. Default is 65. Estimate `128 MiB + 512*nx*ny*nz` bytes and reject above configured budget, x86 <=1536 MiB or x64 <=4096 MiB; actual Windows 129³ solver high-water was ~961 MiB. Record estimate, architecture, requested/actual counts and solver-reported high-water separately; never silently retry/coarsen. Default memory limit is 1536 MiB/x86, 4096 MiB/x64.

`run_tool` returns only for exit0; `ExternalToolError(RuntimeError)` carries
`.result` JSON diagnostics for nonzero exit, timeout, log overflow or lifetime
failure. Invalid input raises ValueError; cancellation raises CancelledError.
Each run verifies actual version/architecture/hashes through a private managed
probe; probe_tool uses an internal unchecked runner to accept recognized APBS
version exit13 without recursion. Generic run_tool does not infer expected
scientific output filenames: feature callers validate nonempty artifacts.

### Domain request dictionaries

`TimelineDoc = {schema_version:1,baseline_scene:str,fps:int,frame_count:int,keyframes:list}`; each keyframe has exactly `id:str,label:str,frame:int,scene:str|null,state:int,view:list[18 numbers],interpolation:'hold'|'smooth'`. IDs match `[A-Za-z0-9_-]{1,64}` and are unique (capture generates UUID hex); labels <=256 characters; scene names 1..256 characters without NUL. First keyframe is frame1, last is frame_count; single-keyframe duration is1. Array order strictly increases. Each left keyframe controls its outgoing interval: linear-time shortest-arc SLERP, equal projection flag, exact endpoints. Scene null inherits the preceding explicit scene or required uniquely named managed baseline captured at creation.

`edit_keyframe` actions are exactly `add,update,remove,move_up,move_down,set_fps`; return a validated new document, never partially mutate the input. Add takes a complete captured row in values and no keyframe_id; update takes existing ID and a subset of label/frame/scene/state/view/interpolation (ID immutable); duplicate frames fail. Remove takes ID/no values and refuses the last remaining row; removing first resets the next frame to1, removing last recomputes frame_count. Move takes ID/no values, swaps frame positions with the adjacent row then sorts; boundary move is a no-op. set_fps takes no ID and exactly `{fps:int}`. Every edit recomputes frame_count from last row.

`MapRecord = {name,state,source_path,source_sha256,format,interpretation,grid,load_matrix,world_matrix,value_sha256,verified,derived}`; `grid` is `grid_metadata` of source-file physical geometry, `load_matrix` is the native matrix captured immediately after validated fresh loading, and `world_matrix` is the current native matrix. Both matrices are row-major 16 numbers acting on column coordinates. Current physical points are `(world_matrix @ inverse(load_matrix)) @ grid_point`; applying world_matrix directly to an MRC grid_point would double-count an origin already in source geometry. Preserve load_matrix when making registered copies. `derived` is exact owned display names. Unassociated session maps have `verified:false`, nullable source fields and may only display. `DisplaySpec = {kind:'mesh'|'surface'|'volume',level:float,color:str,opacity:float,visible:bool,volume_ramp:list[float]}`; volume_ramp consists of ordered five-tuples value/r/g/b/alpha, min two/max 32 stops, finite channels 0..1. Default mesh level 1, cyan, opacity 1; volume ignores isolevel and uses its explicitly supplied ramp.

`DensityRequest = {map_path:str,format:'dx'|'mrc'|'ccp4',interpretation:'auto'|'origin'|'starts',source_state:int,map_name:str|null,display:DisplaySpec,registration:null|dict,render:RenderSpec}`. `map_name` refers to an associated map already in the snapshot; null loads fresh file state 1. Registration is `{kind:'matrix',matrix:list[16],copy_name:str}` or `{kind:'align',mobile:str,target:str,mobile_state:int,target_state:int,selection:str,algorithm:'align'|'super',cutoff:float,cycles:int,model_copy_name:str,copy_name:str}`. For CLI fresh map source_state must be 1; associated GUI state must match validated source metadata. Auto rejects simultaneous nonzero MRC origin/starts; explicit origin requires format mrc, explicit starts uses ccp4 interpretation, and loader format/report reflect that choice.

`PotentialRequest = {mode:'prepared'|'prepare'|'import',pqr_path:str|null,dx_path:str|null,selection:str,state:int,units:'kBT/e'|'V'|'mV'|'unknown',display_units:<same>,temperature:float,preparation:dict,solver:dict,ramp_limit:float,render:RenderSpec,tools:dict}`. Preparation fields are `force_field:'PARSE'|'AMBER'|'CHARMM'`, `ph:float` (0..14), `protonation:'propka'|'preserve'`, `drop_water:bool`; defaults PARSE,7,propka,false. Explicit protein selection required for prepare; supported protein/water handling is validated before tool invocation, unsupported selected ligand/metal/residue fails. Solver fields are `grid:list[3 int]`, `solute_dielectric:2.0`, `solvent_dielectric:78.5`, `salt_molar:0.15`, `ion_radius:2.0`, `probe_radius:1.4`, `coarse_padding:40.0`, `fine_padding:20.0`; paddings are total per-axis expansion, positive, coarse>fine and sufficient for displayed radii+probe. Fixed LPBE, mg-auto, symmetric ±1 ions, bcfl mdh, chgm spl2, srfm smol, swin .3, sdens 10; center from explicit-state PQR bounds. Temperature default 298.15 K, allowed 250..400; positive finite dielectrics/radii, salt 0..2 M, ramp_limit>0 (default 5 kBT/e). Unknown units cannot be converted. Imported V/mV needs explicit temperature only when conversion involves kBT/e. All defaults are recorded.

Computed potential always has raw units kBT/e; reject a different `units` in
prepared/prepare requests and use `display_units` for explicit conversion.
Every potential inventory, including prepared/prepare, conditionally adds
`display.dx` when conversion is requested; retain raw potential.dx unchanged.
`ramp_limit` is expressed in display_units and labelled accordingly. Unknown
units support only same-unit display, never conversion to/from a known unit.
