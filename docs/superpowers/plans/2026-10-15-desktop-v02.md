# MolScene Desktop v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a tested native PyMOL workbench with richer rendering, state-correct analysis, reproducible exports, and v0.2.0 GitHub assets.

**Architecture:** Keep the upstream Qt window and attach a MolScene dock. Share instance-bound scientific functions between isolated CLI contexts and the live controller; snapshot long jobs into independent processes. Keep Qt optional and preserve existing file-output safeguards.

**Tech Stack:** Python >=3.10, separately installed PyMOL, optional PySide6-Essentials 6.8.1, standard-library unittest/QtTest, existing Pillow image checks.

**Spec:** `docs/superpowers/specs/2026-10-15-molscene-desktop-design.md`

## Global Constraints

- All task files, worktrees, runtime environments, caches, temporary files, screenshots, and distribution assets stay on F:. Do not modify the separately installed PyMOL.
- Original code remains MIT; do not copy commercial code, binaries, licenses, or UI resources into the repository. Retain upstream component attribution.
- CLI defaults and old report fields/types remain compatible; add integer schema_version=2. Import/help must work without Qt/PyMOL.
- Explicit positive state for every scientific operation; validate actual coordinate presence for every involved object without singleton fallback.
- Contacts: default cutoff 4 Å, heavy atoms, unique undirected pairs, no self-pairs, maximum 100000; report failure rather than truncation. Draw at most the shortest 200 pairs, export all rows.
- SASA: dot_solvent=1, solvent_radius=1.4 Å, dot_density=3, default non-solvent heavy-atom context and blank+A altloc; target is a context subset. Merge context into one temporary object, preserve source mapping, do not mutate original B-factors/coordinates/settings.
- Preserve lexical link/reparse checks, canonical Windows alias/input containment checks, explicit overwrite, fixed owned artifacts, staged commit, and relative artifact paths.
- Qt/live-scene operations run on the main thread. Ray/SASA/batch jobs use immutable snapshots and independent worker processes; never build shell commands from selections/paths.
- GUI PML replays the bundled PSE; CLI coordinate PML remains independent of MolScene. Document these separate replay contracts.
- User approved design and explicitly delegated all subsequent planning, implementation, review, testing and GitHub publishing; no further stage confirmation is required.

## Review Focus

1. Mixed/missing states and alternate conformers: use explicit state, reject absent coordinates, never report a state-1 fallback as state 2. Task 1/2 tests.
2. Multiple objects sharing chain/residue/index labels: retain object identity and inter-object surface occlusion. Task 1 tests.
3. GUI native edits outside MolScene: refresh objects, preserve current view, label stale snapshot analysis and do not replay it as current. Task 4/5 tests.
4. Failed/cancelled workers and repeated actions: maintain a usable UI, preserve prior outputs and completed batch items, no false success. Task 3/5 tests.
5. Relocated/unusual paths, links, Windows aliases and clean-package fixtures: avoid parser interpolation and external audit-file dependencies. Task 2/6 tests.

## File Ownership and Execution

Task 1 owns `analysis.py` and its tests. Task 4 initially owns only `desktop/` plus GUI dependency configuration and its tests, so its native-shell work can proceed independently in a separate F: worktree while Task 1 is implemented. Task 2 starts after Task 1 review; Task 3 follows Task 2; Task 5 follows Tasks 2–4. Task 6 owns docs/CI/packaging after feature APIs settle. Integration and whole-branch review are controlled centrally. Each implementation has its own F: worktree and commits only its owned files; do not create subagents from worker tasks.
